# Version 0.1.34 (2026-11-06)

### Features
- **Request-Chosen Collection Match Mode (`IterableMatchMode.CHOOSE`)**:
  - A collection filter with `iterableMatchMode = CHOOSE` lets each request pick between `ANY` and `ALL`. The parameter takes a set of values, and the filter DTO gets an extra `String` parameter `<name>MatchMode` (e.g., `?tagIds=1,2&tagIdsMatchMode=ALL`).
  - `ALL`/`AND` requires every value to be matched, `ANY`/`OR` at least one of them. The value is case-insensitive.
  - The new `@FilterField` attribute `defaultIterableMatchMode` (`ANY` or `ALL`, default `ANY`) applies when the request sends no match mode or an unrecognised one.
  - Works for collection associations by id and through a `targetField` of the element (e.g., `targetField = "spice.id"`). A match mode sent without any values filters nothing.
- **Filtered `/count`**:
  - `GET /{path}/count` now accepts the same filter parameters as `GET /{path}`, so `?category=Electronics` counts only the matching rows. Entities without a filter keep the plain total count.
  - Generated services of filtered entities get `count(<Entity>Filter filter)`. `ForgeReadAspect` count hooks also run for it.

### Breaking Changes
- **`count()` Moved Out of the Base Controller**:
  - `ForgeAbstractController` (and so `ForgeController`) no longer declares `count()`. The `/count` endpoint is now generated in each controller, like `findAll`.
  - Hand-written subclasses that override `count()` or call `super.count()` need to be updated: call `service.count()` (or `service.count(filter)`) instead.

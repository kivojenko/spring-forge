# Version 0.1.32 (2026-10-26)

### Features
- **`IterableMatchMode.ALL` through a `targetField`**:
  - `@FilterField(targetField = ..., iterableMatchMode = IterableMatchMode.ALL)` on an entity collection now generates a `Set` of the target's type instead of a single value (e.g., `Set<String> ingredients` for `targetField = "ingredient.id"`).
  - Every supplied value must be matched by some element of the collection, and the values may sit on different elements. Each value is compared with `eq` and gets its own `any()`; these are AND-ed together (`entity.productIngredients.any().ingredient.id.eq(a)` AND `….eq(b)`).
  - Binds from a comma-separated list (`?ingredients=a,b`) or repeated parameters (`?ingredients=a&ingredients=b`). Blank values are skipped, and `orNull` also matches rows whose collection is empty.
  - The default `ANY` is unchanged and still takes a single value. To match any of several values, combine it with a `*_ANY` string match mode (e.g., `EQUALS_ANY`). This works for `String` targets only.

- **Plain List Endpoints with `listType`**:
  - Added the `ListType` enum and the `listType` attribute on `@WithRestController` (`PAGE` by default).
  - With `listType = ListType.LIST`, `GET /{path}` returns a plain `List` of every match. It accepts `sort` and every filter parameter, but not `page` / `size`.
  - Added sorted list retrieval methods to `ForgeService`.

- **Collection Keys in `@GetOrCreate`**:
  - A key field may go through a collection. The entity matches when any element has the given value, and a created entity gets the value added to the collection.
  - Supports `@ElementCollection` of basic values (`"synonyms"`) and entity collections keyed by the element's `@Id` (`"casNumbers.number"`), including collections inside `@Embedded` objects.
  - Collection keys combine with plain fields and other `@GetOrCreate`s. When several entities match, the finder is `findFirstBy…OrderBy<Id>Asc`, so the lowest ID wins.
  - `null` collections and `@Embedded` objects are initialized on create.
  - Unsupported shapes are rejected at compile time with an `Unsupported @GetOrCreate key` error: maps, entity collections not keyed by `@Id`, collections of embeddables, `mappedBy` sides, and collections reached through a related entity.

- **Creating Missing Related Entities in Composite Keys**:
  - A nested key field ending at a related entity's ID (e.g., `"country.code"`) now fetches that entity by ID, or creates it when missing, through a generated `getOrCreate<Relation>` helper on the service.
  - Relations with a database-generated ID (`@GeneratedValue`) are still linked by reference and must already exist.

- **Case-Insensitive Prefix / Suffix String Matching**:
  - Added `STARTS_WITH_IGNORE_CASE` and `ENDS_WITH_IGNORE_CASE` to `StringMatchMode`, plus their multi-value counterparts `STARTS_WITH_ANY_IGNORE_CASE` and `ENDS_WITH_ANY_IGNORE_CASE`.

- **`@FilterSearchField` through Collections**:
  - `targetField` on a `@FilterSearchField` can now point at a field of an entity collection's elements (`aliases.value`) or of a collection of embeddables (`links.label`).
  - The search matches through an ID subquery, so a row whose several elements match is returned once.

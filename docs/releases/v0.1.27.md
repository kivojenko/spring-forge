# Version 0.1.27 (2026-09-15)

### Breaking Changes
- **Default Name for Presence Filters**:
  - `@FilterField(isPresent = true)` without an explicit `name` now exposes the parameter as `has<Field>` (e.g., `description` → `hasDescription`, `dye` → `hasDye`) instead of the field name.
  - Clients calling unnamed presence filters by the field name (e.g., `?dye=true`) must switch to the `has<Field>` name, or set `name` explicitly to keep the old one.
- **Derived Query Names for `targetField`**:
  - A generated `findBy…` is now named after the property it reads, so a `targetField` filter changes name: `findByCategory(String)` → `findByCategory_Name(String)`. Callers of the old names must be updated. See *Fixes* for why the old names could not work.

### Fixes
- **`targetField` on `@Embedded` Fields**:
  - `@FilterField(targetField = ...)` on an `@Embedded` / `@Embeddable` field now resolves relative to that field for both the generated QueryDSL path and the filter parameter type (e.g., `dye` + `targetField = "colorIndex"` → `entity.dye.colorIndex`, `Long`).
  - Previously the target was treated as an absolute path from the root entity (`entity.colorIndex`), generating an incorrect predicate.
  - Applies to presence filters and to value filters (e.g., exact/range parameters `color`, `minColor`, `maxColor` on an embedded `color.colorIndex`).
- **`@FilterField` on an `@ElementCollection` of Scalars**:
  - Annotating a collection of strings, numbers, dates, booleans or enums directly no longer fails annotation processing while looking for an `@Id` on the element type; it now filters element-wise, like a collection `targetField`.
- **Derived Query Names for `targetField`**:
  - Generated `findBy…` methods are now named after the property they actually read (`findByCategory_Name`, `findByDye_ColorIndex`) instead of after the annotated field with the target's type (`findByCategory(String)`), which Spring Data could not resolve.
  - Filters that cannot be expressed as a derived query — collection targets and `IterableMatchMode.AMOUNT` — no longer generate one; they are served by `toPredicate()` only.
- **Presence Filter Name Collisions**:
  - An unnamed presence filter next to another `@FilterField` on the same field is no longer silently dropped from the filter DTO or OR-merged into the other filter's predicate; the new `has<Field>` default gives each its own parameter.

### Documentation
- README: documented the `has<Field>` default name and `targetField` on `@Embedded` values, with an embedded presence filter example.
- README: documented collection targets and `@ElementCollection` filters, and how `targetField` is reflected in derived query names.
- `@FilterField` Javadoc:  updated `name`, `isPresent` and `targetField` descriptions.

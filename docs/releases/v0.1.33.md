# Version 0.1.33 (2026-11-02)

### Features
- **Boolean Filter Parameters with Several Targets**:
  - Repeated `@FilterField` mappings that share a `name` on `Boolean` targets now ask whether any target is set: `true` matches rows with at least one target set, `false` rows with none set (e.g., `?uvFilter=true` for `chemicalUvFilter` and `mineralUvFilter`).
  - This replaces the previous behavior, where such a parameter read only the first mapping. Types other than `String` and `Boolean` still read only the first mapping.
  - Presence filters and collection targets are not covered and keep their existing behavior.
  - The repository gets one finder per property, however many parameters read it (e.g., `findByChemicalUvFilter` for both `uvFilter` and `chemicalUvFilter`).

### Bug Fixes
- **Ranges inside `OR` Families**:
  - A `RANGE` or `EXACT_OR_RANGE` member of an `OR` family now has its min and max AND-ed with each other before the range joins the family, so `?minSpf=25&maxSpf=35&minMaxSpf=35&maxMaxSpf=45` means `(spf in 25..35) OR (maxSpf in 35..45)`.
  - Previously each bound was OR-ed into the family separately, so a row satisfying only one bound of a range matched.
  - Ungrouped filters and `AND` families are unchanged.

# Version 0.1.26 (2026-09-14)

### Features
- **Presence Filtering with `@FilterField(isPresent = true)`**:
  - Added `isPresent` attribute to `@FilterField` that turns a filter into a presence check exposed as a `Boolean` query parameter.
  - `true` maps to `isNotNull()` (`isNotEmpty()` for collections), `false` maps to `isNull()` (`isEmpty()` for collections); match modes are ignored.
  - Without an explicit `name`, the parameter defaults to `has<Field>` (e.g., `description` → `hasDescription`), so a presence filter can sit next to a regular value filter on the same field.
  - Supports `targetField`, including on `@Embedded` value objects (e.g., `@FilterField(targetField = "colorIndex", isPresent = true)` on `dye` → `?hasDye=true` checks `dye.colorIndex`).
  - `RepositoryGenerator` skips derived query methods for presence filters.
- **Single-Value `@WithGetEndpoint` Methods**:
  - Entity methods annotated with `@WithGetEndpoint` that return a single, non-generic value (e.g., `Integer getBooksCount()`) now generate a GET endpoint returning that type directly (`GET /{id}/booksCount`).
  - Introduced `ReadSingleMethodEndpointRelation` and extended `EndpointRelationResolver` to pick it for non-generic return types.
- **Self-Referencing Many-to-Many Associations**:
  - Verified endpoint generation for entities with self-referencing `@ManyToMany` collections (e.g., `Category` `parents` / `children`) via new example model and tests.

### Fixes
- **`targetField` on `@Embedded` Fields**:
  - `@FilterField(targetField = ...)` on an `@Embedded` / `@Embeddable` field now resolves relative to that field (`dye.colorIndex`) for both the generated QueryDSL path and the filter parameter type; previously it was treated as an absolute path from the root entity (`entity.colorIndex`), generating an incorrect predicate.
- **Explicit `allowSlashes = false` Overrides Global Config**:
  - `JpaEntityRequirements` now reads `allowSlashes` only when explicitly set on `@WithRestController`, so `@WithRestController(allowSlashes = false)` disables slash-containing IDs even when `controller.allowSlashes` is enabled globally; entities without the attribute still fall back to the global setting.

# Version 0.1.28 (2026-09-30)

### Breaking Changes
- **Derived Query Names for `targetField`**:
  - Generated repository `findBy…` query methods now reflect the actual property path targeted by `@FilterField(targetField = ...)` (e.g., `findByCategory_Name(String)` instead of `findByCategory(String)`). Callers relying on the old method names must update their method calls.
  - Filter fields that cannot be mapped to Spring Data JPA derived queries (such as collection targets and `IterableMatchMode.AMOUNT`) no longer generate invalid `findBy…` methods, avoiding startup validation failures and relying solely on `toPredicate()`.

### Features
- **Filter Families (`family` attribute & `@FilterFamily`)**:
  - Added `family` attribute to `@FilterField` to group related filter fields together.
  - Within a family, filters are combined with `OR` logic by default, while independent families and ungrouped filters are combined with `AND` logic in generated `toPredicate()` methods.
  - Introduced class-level `@FilterFamily` (and repeatable `@FilterFamilies`) along with `FamilyMatchMode` (`OR`, `AND`, `EXISTS`).
  - Added `FamilyMatchMode.EXISTS`, requiring at least one target field within the family to hold a non-null/non-empty value, while optionally applying specific field predicates if filter parameters are provided.
- **Multi-Value String Match Modes (`*_ANY`)**:
  - Added multi-value match modes to `StringMatchMode` (`EQUALS_ANY`, `EQUALS_IGNORE_CASE_ANY`, `CONTAINS_ANY`, `CONTAINS_IGNORE_CASE_ANY`, `STARTS_WITH_ANY`, `STARTS_WITH_IGNORE_CASE_ANY`, `ENDS_WITH_ANY`, `ENDS_WITH_IGNORE_CASE_ANY`).
  - Generates query filter parameters typed as `Set<String>` (e.g., accepting comma-separated values or repeated parameters) and evaluates them using `OR` logic across all supplied values.
  - Seamlessly integrates with `@ElementCollection` fields and filter families.
- **Filtering on `@ElementCollection` of Scalars & Collection Targets**:
  - `@FilterField` can now directly annotate `@ElementCollection` fields (or reach collection targets via `targetField`) of scalar types (strings, numbers, booleans, enums).
  - Matches element-wise against collection items using generated `exists` subqueries, supporting nested collection paths in `@Embedded` structures where QueryDSL `any()` is not serializable.
  - Presence filtering (`isPresent = true`) on collection targets verifies collection non-emptiness (`isNotEmpty()` / `isEmpty()`).

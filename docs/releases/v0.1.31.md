# Version 0.1.31 (2026-10-12)

### Features
- **Composite Key Lookups in `@GetOrCreate`**:
  - Updated `@GetOrCreate` to support composite lookup/creation keys via the `fields` attribute (`String[] fields() default {"name"}`), replacing the single `field` attribute.
  - Supports combinations of direct and nested property paths (e.g., `{"name", "country.code"}`), looking up entities against all specified fields and creating entities with all key properties populated.
  - Generates composite query methods in the repository layer (e.g., `findByNameIgnoreCaseAndCountry_CodeIgnoreCase(...)`) with case-insensitivity support.

- **Repeatable `@GetOrCreate` Annotations**:
  - Made `@GetOrCreate` repeatable via `@GetOrCreates`, allowing multiple distinct get-or-create definitions on the same entity.
  - Generates uniquely named service methods for each key (e.g., `getOrCreateBySku`, `getOrCreateByName`, `getOrCreateByBrandAndName`) while maintaining `getOrCreate` for single annotations.
  - Generates REST endpoints sharing the same base path (e.g., `/get-or-create`) and uses Spring MVC request parameter matching (`@PostMapping(params = {...})`) to route requests to the appropriate handler.

- **AOP Read Hooks with `ForgeReadAspect`**:
  - Introduced `ForgeReadAspect<E>`, an abstract Spring AOP aspect base class for intercepting read operations in `ForgeService`.
  - Provides `@Before` and `@AfterReturning` lifecycle hooks for `getById`, `findAll` (including paged and QueryDSL filtered queries), `readAssociation`, `count`, and `exists`.
  - Enforces strict entity type checking (`entityType()`) to prevent aspect execution across unrelated entity hierarchies.

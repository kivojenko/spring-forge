# Version 0.1.30 (2026-10-06)

### Features
- **Granular Jackson JSON Views (`listView` and `detailView`)**:
  - Added `listView` (`Class<?> listView() default Void.class`) and `detailView` (`Class<?> detailView() default Void.class`) attributes to `@WithRestController`.
  - Enables configuring distinct Jackson `@JsonView` serialization classes for collection endpoints (`findAll`) versus single-entity detail endpoints (`getById`, `update`, `patch`, `getOrCreate`).
  - Both attributes automatically fall back to `view()` when unspecified, maintaining backwards compatibility.
  - Allows optimizing payload size and serialization overhead for list queries (e.g., summary projections) while supporting detailed views for single-entity retrievals.

- **Multi-Field Text Search (`@FilterSearchField` & `@FilterSearchFields`)**:
  - Added `@FilterSearchField` (and repeatable `@FilterSearchFields`) annotation for entity fields and associations.
  - Generates a unified `String search` (or custom named parameter via `name`) on generated filter DTOs.
  - Matches across all annotated fields using `OR` logic within `toPredicate()`, while combining with other non-search filter fields using `AND`.
  - Supports configurable `StringMatchMode` (e.g., `CONTAINS_IGNORE_CASE`, `STARTS_WITH_IGNORE_CASE`, `EQUALS`) and navigation into related entities via `targetField`.

- **Default and Dynamic Endpoint Sorting (`sort` attribute)**:
  - Added `sort` attribute (`String[] sort() default {}`) to `@WithRestController`, `@WithEndpoints`, and `@WithGetEndpoint`.
  - On `@WithRestController`, applies default sort configurations to `@PageableDefault` on generated `findAll` endpoints.
  - On association endpoints (`@WithEndpoints`) and custom GET endpoints (`@WithGetEndpoint`), annotates generated controller methods with `@SortDefault` and generates a `Sort sort` parameter.
  - Added reflection-cached, type-safe in-memory sorting utilities in `ForgeAbstractController` to dynamically sort returned entity collections and scalar iterables.

- **View-Aware Association Loading (`readAssociation`)**:
  - Generated `GET /{path}/{id}/{sub}` association endpoints for `@OneToMany` and `@ManyToMany` relationships configured with a Jackson `view` now utilize `ForgeService.readAssociation(id, attribute, view)` for optimized batch query resolution.
  - Eliminates N+1 queries by pre-fetching only the associations and properties rendered by the specified `@JsonView` definition (plus `EAGER` associations) in a fixed number of queries determined by the entity graph shape.
  - Recursively follows entity associations matching the view constraints, handling self-referencing relationships cleanly.
  - What the view serializes is determined from entity annotations (`@JsonView`, `@JsonIgnore`, write-only `@JsonProperty`).
  - `ForgeService.readAssociation` is public and overridable for custom data-fetching pipelines.

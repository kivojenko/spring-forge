# Version 0.1.21 (2026-08-11)

### Features
- Get-or-Create by Custom Field: `@GetOrCreate` now supports `field` and `ignoreCase` options, enabling lookup/creation by any entity property (not tied to `HasName`). Generated repositories add `findBy<Field>`/`findBy<Field>IgnoreCase` methods as needed, and services/controllers expose `/get-or-create` endpoints using the configured field type and name.
- OR-Combined String Filters: When multiple `@FilterField` mappings share the same filter name and are `String`-typed, the generated predicate now OR-combines all mapped properties using the primary mapping's `StringMatchMode` (e.g., search simultaneously in `name` and `alternativeNames.any().name`). This provides broader, more intuitive search without extra round-trips.

### Bug Fixes
- Inherited Target Field Resolution: `@FilterField(targetField = "...")` now correctly resolves target properties declared in superclasses. This fixes filtering scenarios where the associated entity's property is inherited (e.g., filtering by `car.name` when `name` is defined on a base class `Vehicle`).
